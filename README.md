# 密文信封

密文信封是一个浏览器端的文本加密工具。发送者用口令把文本封装成一段可复制的密文，接收者用同一口令解密。修改密文或输入错误口令时，系统会拒绝解密。项目用一个完整的收发流程演示口令派生、对称加密和完整性验证。

## 本地运行

下载源码，进入含有 `index.html` 的项目目录。使用 Python 3 启动静态文件服务即可，无需安装前端依赖。

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

在现代浏览器打开 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)。文本加密和解密在浏览器中执行，静态服务只提供页面文件。Web Crypto 需要安全上下文，本地回环地址可直接使用。桌面端近期版本的 Chrome、Edge、Firefox 和 Safari 均支持所需的 Web Crypto 能力；通过 `http://` 非 localhost 地址打开时，浏览器会禁用 Web Crypto，导致页面无法加密。

## 演示流程

1. 在 **加密** 模式下输入一段虚构消息和演示口令，点击 **生成密文信封**，再点击 **复制结果**。同样的消息和口令重复加密会得到不同的密文。
2. 切换到 **解密** 模式，粘贴密文信封，输入原口令并点击 **解密文本**，确认输出与原消息相同。
3. 保留正确口令，将密文最后一段的首字符换成另一个 Base64url 字符。例如，首字符为 `A` 时换成 `B`，否则换成 `A`。再次解密，页面应提示验证失败。

## 加密设计

1. 明文按 UTF-8 编码，支持中文和表情，最大 64 KiB。口令最大 1,024 字节，区分大小写，空格参与派生。
2. 每次加密使用 `crypto.getRandomValues` 分别生成 16 字节盐和 12 字节初始化向量（IV）。以口令和盐为输入，通过 PBKDF2-HMAC-SHA-256 迭代 600,000 次，派生 256 位密钥。
3. 使用 AES-256-GCM 加密，产生密文和 128 位认证标签。版本标识 `CE1` 作为附加认证数据。
4. 信封格式为 `CE1.<salt>.<iv>.<ciphertext+tag>`。后三段使用无填充的 Base64url 编码。解密前会校验信封版本、各字段的编码和长度。认证通过后才返回明文。

参考 [W3C Web Cryptography](https://www.w3.org/TR/WebCryptoAPI/) 和 [NIST SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final)。

## 安全边界

- 拿到信封的人可以离线尝试口令。PBKDF2 提高每次猜测的成本，口令仍需有足够的随机性。
- 收发双方需要通过独立的可信渠道交换口令。持有同一口令的人都可以生成有效信封，因此信封无法证明发送者身份。
- 忘记口令后无法恢复明文。请在可信设备和浏览器中运行，避免用课程演示处理重要数据。

## 测试

在项目目录使用 Node.js 22 或更新版本运行：

```powershell
node --test
```

测试覆盖加密解密、随机化、错误口令、密文篡改和格式校验。

## 项目结构

| 文件 | 说明 |
| --- | --- |
| `index.html` | 页面结构，声明内容安全策略 |
| `style.css` | 页面样式 |
| `src/crypto.mjs` | 加密与解密核心：口令派生、AES-256-GCM 封装、信封编解码与校验 |
| `src/app.mjs` | 界面交互：加解密模式切换、表单校验、结果展示与复制 |
| `tests/crypto.test.mjs` | 加密核心的单元测试，使用 Node.js 内置测试运行器 |

页面不引入任何第三方前端库，全部为原生 HTML、CSS 和 JavaScript 模块；加密逻辑与界面逻辑分离，`src/crypto.mjs` 可独立复用。
